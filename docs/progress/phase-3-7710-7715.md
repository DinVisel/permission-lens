# Phase 3 — ERC-7710 and ERC-7715

Weeks 9–12. Source: [`IMPLEMENTATION_PLAN.md` §9](../../IMPLEMENTATION_PLAN.md#phase-3--erc-7710-and-erc-7715-weeks-912).

**Status:** ⚪ not started.

## Tasks

- [ ] 7710 typed-data parser: validate the domain (`DelegationManager`, version `"1"`), decode `Delegation` and `Caveat[]`; exclude `signature` and `args` from anything presented as "signed".
- [ ] Enforcer decoders: Timestamp, AllowedTargets, AllowedMethods, ValueLte, NativeTokenTransferAmount, ERC20TransferAmount, LimitedCalls, Redeemer; then periodic and streaming enforcers.
- [ ] Registry entries for DelegationManager and enforcer deployments (from MetaMask's official deployment list only).
- [ ] Rules PL-7710-001…009.
- [ ] Redelegation: accept a chain of delegations; render the accumulated scope.
- [ ] 7715 request parser with versioned adapters (pin the spec revision) and response parser (`context` → 7710 delegations when the manager is known).
- [ ] Rules PL-7715-001…005, especially the request↔context cross-check.
- [ ] PL-GEN-002: typed-data execution intents for recognized delegates that accept them.

## Acceptance criteria

- [ ] Fixtures produced by the real MetaMask delegation framework tests decode correctly.
- [ ] A mismatched 7715 response (limit removed in `context`) fires PL-7715-003.

## Notes

The `Grant` IR (`packages/core/src/types.ts`) already has `parent`/`children`
fields for redelegation chains and a `Restriction` union covering the
caveat/enforcer types this phase needs — the type-level groundwork from
Phase 1 should carry over without rework. The `standard` field also already
includes `"7710"` and `"7715"` as valid values; only the parsers are missing.
