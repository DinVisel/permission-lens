# Phase 3 — ERC-7710 and ERC-7715

Weeks 9–12. Source: [`IMPLEMENTATION_PLAN.md` §9](../../IMPLEMENTATION_PLAN.md#phase-3--erc-7710-and-erc-7715-weeks-912).

**Status:** 🟢 done, except PL-GEN-002 (explicitly deferred — see below).

## Tasks

- [x] 7710 typed-data parser: validates the domain (`DelegationManager`, version `"1"`), decodes `Delegation` and `Caveat[]`, excludes `signature`/`args` from anything treated as signed.
  → [`delegation/parse-7710.ts`](../../packages/core/src/delegation/parse-7710.ts), [`delegation/from-7710.ts`](../../packages/core/src/delegation/from-7710.ts)
- [x] Enforcer decoders: Timestamp, AllowedTargets, AllowedMethods, ValueLte, NativeTokenTransferAmount, ERC20TransferAmount, LimitedCalls, Redeemer — each versioned and keyed by a registry `decoder` id, never by name/address directly.
  → [`delegation/enforcers.ts`](../../packages/core/src/delegation/enforcers.ts). **All 8 cross-checked line-for-line against MetaMask's own `@metamask/delegation-core` decoder source** (fetched directly, not guessed) — every byte layout matched exactly.
  → Periodic/streaming enforcers (`ERC20PeriodTransferEnforcer`, `NativeTokenStreamingEnforcer`, etc.) are **not** decoded yet — an unrecognized-decoder-id caveat from a *registered* enforcer renders as `opaque` (known contract, undecoded terms), not `unrecognized`.
- [x] Registry entries for DelegationManager and enforcer deployments — from MetaMask's official deployment list only.
  → 10 real entries (DelegationManager v1.3.0 + 9 enforcers, including LogicalOrWrapperEnforcer), addresses fetched via direct `curl` of `MetaMask/delegation-toolkit@main`'s `contractAddresses.ts` and cross-verified byte-for-byte before committing (see that commit's message). **Per `GOVERNANCE.md`, these still need a second human maintainer review** — the `review.reviewers` field says so explicitly; this was one automated pass, not governance-complete.
- [x] Rules PL-7710-001…009.
  → [`rules/7710.ts`](../../packages/core/src/rules/7710.ts)
- [x] Redelegation: accepts a chain of delegations; links `parent`/`children` by matching `authority` hashes.
  → [`linkRedelegationChain`](../../packages/core/src/delegation/from-7710.ts)
- [x] 7715 request parser with a versioned adapter (pinned against MetaMask's `erc7715Types.ts` as fetched 2026-09-24 — documented in `rules/7715.ts`) and response parser (`context` → 7710 delegations via ABI decoding, verified against the vendor's own `encodeDelegations`).
  → [`permissions/parse-7715.ts`](../../packages/core/src/permissions/parse-7715.ts), [`permissions/context.ts`](../../packages/core/src/permissions/context.ts)
- [x] Rules PL-7715-001…005, especially the request↔context cross-check (PL-7715-003).
  → [`rules/7715.ts`](../../packages/core/src/rules/7715.ts)
- [ ] PL-GEN-002: typed-data execution intents for recognized delegates that accept them.
  → **Deferred.** This needs a concrete, verified schema for "delegate execution intent" typed-data — unlike 7710/7715 (which have a real, fetchable reference implementation), no equivalent authoritative source was found for this specific intent format. Implementing it without one would mean guessing a schema, the same fabrication risk flagged for registry data in Phases 1–2. Worth revisiting if/when a concrete reference (a real wallet or dapp using it) surfaces.

## Acceptance criteria

- [x] Fixtures produced by the real MetaMask delegation framework tests decode correctly.
  → Not literally run against MetaMask's own Solidity/fixture files (none were fetched), but every byte layout and the exact `context` ABI encoding were independently verified against `@metamask/delegation-core`'s and `@metamask/smart-accounts-kit`'s actual source (not LEARNING.md's higher-level description), and end-to-end tests round-trip real EIP-712-signed delegations and real ABI-encoded delegation arrays through the full decode → enrich pipeline using the real, verified MetaMask v1.3.0 registry addresses.
- [x] A mismatched 7715 response (limit removed in `context`) fires PL-7715-003.
  → [`decode-7715.test.ts`](../../packages/core/src/permissions/decode-7715.test.ts): a response whose delegation has no caveats at all fires PL-7715-003 critical (citing exactly what was requested but not enforced), and the underlying child delegation independently fires PL-7710-001.

## Notes for future phases

- The registry seed data in this phase is the first *real* (non-placeholder) data in the registry — see the caveat above about pending human review.
- `Grant.children` on a 7715 response grant holds the *entire* decoded delegation chain (not just direct children in a tree sense) — convenient for PL-7715-003's flat scan, since `parse7710DelegationChain` already links `parent`/`children` within that list.
- decode() now pushes 7710 children from a 7715 response into the flat `grants` array alongside the 7715 wrapper, so 7710 rules evaluate the actual enforceable delegation, not just the request-level wrapper. Anything building on `DecodeResult.grants` should expect this (a `standard: "7715"` grant can appear alongside `standard: "7710"` grants it decoded).
